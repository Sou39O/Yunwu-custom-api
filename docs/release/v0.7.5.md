# v0.7.5 自动重试上限与「停止」修复

## 概述

修复自动重试链**没有轮数上限**导致的无限循环，并让「停止」真正能掐断整条重试链。

## 问题

### 无限重试链

自动重试的设计是「上一轮全失败就再排一轮 20 张」，但**没有任何轮数上限**。只要上游持续拒绝（本例是内容审核把整批都挡掉），链条就会永远跑下去：

- 实测某账号跑到第 **965 轮**
- 累计 **4344 个失败任务**、**4074 次自动重试事件**
- 从 11-10 持续到 11-14，服务进程长期占着 **40 条**到上游的连接

### 「停止」停不掉

`cancelTask` 对已终结的任务会直接 return，压根不处理重试链。而重试链的派生是由**父任务**在终结时触发的——所以：

- 停掉当前这一轮 → 父任务再派生新一轮
- 父任务已 `failed` 时点停止 → 直接返回，什么都不做

用户看到的现象就是「明明点了停止，它还在跑」。

## 修复

### 1. 轮数上限（50 轮）

新增 `AUTO_RETRY_MAX_ROUNDS = 50`。达到上限时按「已完成」收尾并记录日志，不再派生新一轮。

### 2. 停止掐断整条链

新增 `stopAutoRetryChain`：沿 `source_task_id` **向上找到链头、向下递归找到所有派生轮次**，然后：

- 把其中未终结的任务取消（同时清空队列、取消未完成的 batch slot）
- 给链上每个开了 `autoRetry` 的任务写入 `completedAt` 与 `stoppedByUser`，阻断后续派生

同时修掉了已终结任务提前 return 导致链不被掐断的问题。

## 存量数据清理

对受影响的本地库做了止损（**清理前已备份**，数据库完整性校验 `ok`）：

- 取消 2 个在跑的任务
- 给 **4041 条**重试链封口
- 清理后活跃任务为 0

所有历史任务与作品记录均保留，只改状态字段，未删除任何数据。

## 验证

- API 102 个单测全部通过（新增 3 个：整链停止、从中间轮次停止、50 轮上限）
- 数据库 `integrity_check` = ok，4726 个任务、916 个资产记录完整

## 升级说明

- 数据库无 schema 变更
- 桌面用户可在应用内更新到 0.7.5
- 若你需要更多轮重试，可调整 `AUTO_RETRY_MAX_ROUNDS`；但建议先确认持续失败的具体原因（内容审核 / 额度 / 权限）
