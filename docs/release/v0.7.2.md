# v0.7.2 作品库批量下载

## 概述

作品库支持多选后一次性打包下载，文件名按「日期 + 哈希前几位」生成。批量任务（一次生成多张图）与单张作品走同一条下载路径。

## 新增功能

### 批量下载

- 作品库每张卡片新增「加入下载清单」勾选框
- 工具栏提供：全选 / 取消全选、下载所选（显示已选数量）、清空选择
- 单张作品与批量任务可混合选择，一次打包成一个 zip
- 下载为服务端流式生成，边读边发，不把整包攒在内存里

### 文件名规则

```
2026-10-09_86ae2cb5.png
└─────┬────┘ └──┬──┘└┬┘
   日期       哈希   原扩展名
```

- **日期**：作品生成日期（`createdAt` 的 UTC 日期，`YYYY-MM-DD`）
- **哈希**：资产 id 的 SHA-256 前 8 位十六进制。稳定、可复现，同一作品多次下载文件名一致；不读取图片内容，因此不受文件移动影响
- **扩展名**：取自存储 key，缺失时按 mimeType 兜底（`.png` / `.jpg` / `.webp` / `.gif`）
- 极端情况下同名会自动追加 `-2`、`-3` 序号，不会互相覆盖

### 批量任务适配

- 批量任务在作品库里是一张卡承载多张图，勾选这张卡即把该任务**所有成功图片**加入清单
- 失败的槽位不计入选区（一个 `batchSize=4`、成功 3 个的任务，勾选后计数为 3）
- 批量结果弹窗新增「下载全部 (N)」按钮，可直接打包该任务的全部成功图片，无需先勾选
- 删除作品后勾选状态自动收敛，不会拿着已删除的 id 去请求

### 权限与限制

- 沿用单张下载的归属校验：非管理员只能下载自己的作品，越权返回 403
- 未登录 401，空选择 400，单次最多 200 个资产
- 单个资产读取失败不会让整包失败：跳过该文件，并在包内附 `README.txt` 说明跳过数量

## 实现说明

- ZIP 由服务端手写（`src/api/library/zip-writer.ts`），仅 STORED 不压缩。作品库产物都是 PNG / JPEG / WebP 等已压缩格式，再压一遍几乎不省体积，因此不引入 zip 依赖（`fflate` 只作为间接依赖存在，不能直接依赖）
- 端点：`POST /api/library/download`，请求体 `{ assetIds: string[] }`，响应 `application/zip`
- 本地资产直接读文件，S3 / 远端资产走 HTTP 拉取；只留上游 URL 的历史作品按上游地址兜底拉取
- 上游图片下载带回退重试（3 次，指数退避，60 秒超时）；4xx 视为链接失效不重试
- 下载失败的作品会在服务启动 15 秒后、以及之后每 10 分钟由 `AssetPersistenceService` 补存到本地存储（`ASSET_BACKFILL_ENABLED=false` 可关闭）

## 修复

### 批量下载对「只有上游 URL」的作品 100% 失败

Grok Imagine 等模型的上游只返回一个临时图片链接，早期生成的 85 个作品因此在库里没有 `storageKey`，只有 `storage: "remote-url"` 的上游地址。`AssetStorageService.resolveContent` 遇到空 `storageKey` 直接返回空，下载链路把这类作品全部跳过——选满一整个作品库，包里只剩一个 `README.txt`。

现在 `resolveContent` 在没有 `storageKey` 时回退到上游地址，下载时按 URL 拉取；同时生成阶段改为下载成功才落盘、失败重试，并对存量数据做补存，让后续不再产生这类资产。

## 验证

- API 94 个单测、Web 87 个单测全部通过
- ZIP 写出器用 Python `zipfile` 交叉验证：`testzip()` 无损坏、文件数量与大小正确、压缩方式为 STORED、字节与磁盘原文件逐字节一致
- 实测：批量任务（3 成功 + 1 失败）勾选后下载得 3 个文件，内容与各槽位对应；混合下载 6 个文件全部命名正确
- 实测：未登录 401、空列表 400、不存在 id 400、别人作品 403
- 浏览器实测：批量结果弹窗「下载全部 (3)」与工具栏「全选 → 下载所选 (6)」均正确产出 zip 并触发下载
- 下载修复用真实数据回归：某账号作品库 45 个条目（均为上游临时链接、无 `storageKey`）修复前只产出 1 个 `README.txt`，修复后 45 个文件全部进包、`testzip()` 无损坏、无跳过说明
- 补存实测：85 个存量远端作品在一次启动内全部落盘（5 轮 × 20 个），补存后再次整库下载 45 个文件全部命中
