# v0.7.3 修复批量下载与生图持久化

## 概述

修复作品库批量下载在特定数据下 100% 失败的问题，并让生成结果在产出当时就落盘到本地存储；已有的漏网作品由后台服务自动补存。

## 修复

### 批量下载 100% 失败

**现象**：作品库里明明有大量作品，全选后下载得到的 zip 里只有一个 `README.txt`。

**原因**：Grok Imagine 系模型的上游只返回一个临时图片链接。早期生成时如果下载图片字节失败，作品会退化成 `storage: "remote-url"`，数据库里 `storageKey` 为空、只剩上游地址。`AssetStorageService.resolveContent` 遇到空 `storageKey` 直接返回空，下载链路把这类作品全部跳过，于是整包为空。

**修复**：
- `resolveContent` 在没有 `storageKey` 时回退到上游 URL；下载链路按 URL 拉取
- 单张预览的 `/api/assets/:storageKey/content` 走 302 跳转到上游地址
- 生成阶段改为下载字节成功才落盘，失败按 3 次重试（指数退避，60 秒超时）；4xx 判定链接失效直接放弃重试

### 生图结果自动持久化

上游图片 CDN 偶发抽风时，作品只留一个会过期的临时链接，过期后既下载不了也看不了。现在：

- **生成即落盘**：任务成功时立刻把图片字节下载到本地存储（`local` 或 `s3`）
- **后台补存**：`AssetPersistenceService` 在启动 15 秒后把存量中「只有上游 URL」的作品补下载到本地，单次最多连续 10 轮 × 20 个，之后每 10 分钟兜底一次
- 补存成功后写回 `storageKey` / `url`，并在 metadata 里记录 `backfilledAt` 与原始 `upstreamUrl`
- 补存失败的（链接已过期）不会反复重试拉低启动速度：一轮内没有任何进展就收工

配置项：`ASSET_BACKFILL_ENABLED=false` 可关闭后台补存。

## 已知限制

**已经过期的上游链接无法找回。** 若某作品的上游临时链接在补存之前就已失效（HTTP 4xx），其图片字节已不存在于任何地方，数据库记录会保留但内容不可恢复。修复只保证从现在起的作品一定会落盘，以及链接仍有效的存量作品会被补存。

## 验证

- API 97 个单测全部通过（新增 8 个：远端 URL 下载、上游失效跳过、本地与远端混选、补存成功/失败、重试语义）
- Web 87 个单测全部通过
- 真实数据回归（隔离副本，未触碰原始数据库）：
  - 某账号作品库 45 个条目全部为上游临时链接、无 `storageKey`
  - 修复前：整库下载 → 1 个 `README.txt`
  - 修复后：45 个文件全部进包，`testzip()` 无损坏，无跳过说明
  - 补存：85 个存量远端作品在一次启动内全部落盘（5 轮 × 20 个）；补存后再整库下载 45 个文件全部命中

## 升级说明

- 数据库无 schema 变更
- 桌面用户可在应用内更新到 0.7.3
- 升级后首次启动会自动补存存量的远端作品，期间会占用少量带宽
